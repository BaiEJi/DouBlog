# 思维导图性能基准

**正式结果：功能与全量节点检查通过；1000/5000 节点未达到全部操作 100 ms、60 FPS 的性能目标。** 100 节点编辑反馈 33.3 ms，1000 节点为 183.3 ms，5000 节点为 3717.1 ms。5000 节点实际拖动约 55.1 rAF FPS，松手后稳定需 6818.1 ms；实际平移约 43.3 FPS、滚轮缩放约 16.8 FPS。不能以 API 很快返回或拖动预览尚可替代最终编辑反馈。

本报告的方法由 `frontend/tools/mindmap-benchmark.js` 和 `frontend/tools/run-mindmap-benchmark.mjs` 固定。原始结果保存到 [mindmap-performance.json](./mindmap-performance.json)，每个规模完成初始化、API 操作和每项真实手势后立即写入，后续失败仍保留先前规模的证据。原始 `status:complete` 表示本轮执行和数据完整性检查完成；性能目标未全部满足，超限项目另列于 `targetAssessment`。

单位为毫秒；除初始化外，每格为 **callMs / feedbackMs**。反馈包含一次核心稳定等待和两帧绘制；这两个值均为墙钟耗时，不能宣称是纯 CPU 时间。

| 搜索 | 0.5 / 27.4 | 2.6 / 19.8 | 16.4 / 82.7 |
| 定位 | 1.5 / 31.8 | 1.5 / 33.9 | 4.5 / 133.2 |
| 修改节点文本 | 5.3 / 33.3 | 8.3 / 183.3 | 32.9 / 3717.1 |
| 折叠一级分支 | 0.3 / 32.1 | 0.1 / 112.8 | 0.3 / 3074.9 |

## 未达标原因与后续边界

本轮证明纯文本换行优化和稳定内容尺寸生效，也证明它们不足以让全量 SVG 渲染达到目标。源码仍由主线程完成全树布局和 SVG 节点/连线更新；修改一个节点或重挂会触发重排，展开和导入还会恢复大量 DOM 内容。大图平移/滚轮虽主要更新 transform，实际 rAF 间隔仍明显超出 16.7ms。原始长任务与帧统计支持这些瓶颈现象；本轮未采集 CPU/GPU tracing，不能给具体函数或绘制阶段分配精确耗时比例。

进一步工作需要把尺寸测量与批量 DOM 插入分开、减少受影响分支以外的重排/连线更新，并独立验证不同布局与图像/格式组合。Worker 只能在先剥离 DOM 尺寸输入后评估。视窗裁剪可以另设可选大图模式，但会改变“5000 节点全部实际渲染”的测量条件，不能用于把本轮未达标改写为通过。本版没有实现上述后续架构改造。

这是一轮固定树形、指定设备、开发服务器和 headless 浏览器测量；不代表生产打包、多轮 P95、其他设备、深链结构、图像密集数据或真实屏幕 GPU 呈现。大型 PNG/SVG 导出也受浏览器画布/内存上限约束；本轮只对 25 节点验证实际 PNG/SVG/XMind/Markdown 文件下载，以及 XMind/Markdown 主题树往返，不宣称完成 5000 节点这些格式的压力测试。

## 测量范围与方法

- 数据：固定广度优先四叉树，中文主题，100、1000、5000 个节点全部展开。关闭上游视窗裁剪，保留全部 SVG 节点；实时小地图保持启用。初始化、JSON 往返和手势后都核对实际 DOM 节点数。
- 初始化：从构造编辑器到首次完整渲染和两帧绘制完成；没有再次叠加 `whenReady()`。
- `callMs`：API 调用返回的墙钟耗时；异步 API 包含自身 Promise 内的等待，不能称为纯 CPU 耗时。`feedbackMs` 再等待一次核心稳定和两帧绘制，表示可观察反馈。
- 拖节点：在 100% 缩放下定位相邻末端叶子，读取真实 DOM 边界，通过 Playwright 鼠标输入触发 `Drag` 插件。24 个输入步骤，每步间隔 16 ms；单独记录 680 ms 受控悬停，以满足上游 300 ms 碰撞检测节流。必须核对源节点的父 UID 确实变化，单纯移动鼠标不算成功。
- 平移/缩放：实际空白画布拖动和 Ctrl+滚轮，核对画布位移/缩放值确实变化，节点仍完整保留。
- 帧数据：只在手势活动窗口采样 rAF。移动窗口与受控悬停分开，记录平均 rAF 回调频率、首帧延迟、帧间隔中位数/P95/最大值、超过 33.34 ms 的间隔和相对 60 Hz 的估计掉帧。它不是屏幕录像或 GPU 呈现统计。
- 松手反馈：节点拖动/画布平移由浏览器捕获阶段对实际 mouseup 打点，记录到核心稳定和两帧绘制的时间；滚轮在释放 Control 后记录输入结束标记。不会把整个鼠标路径或受控悬停误作核心处理耗时。
- 内存：启用 Chromium 精确内存标志，记录初始化前后、操作后及最终 JS 堆样本；不强制 GC，不等同于进程/GPU 峰值内存。
- 导入导出：测量带产品信封的 JSON 序列化、验证、解析和重新渲染；SVG/PNG/XMind/Markdown 的实际下载与主题树往返由独立 25 节点核心测试检查。

## 优化依据

上游普通文本换行逻辑为每个字符前缀创建 SVG Text 并测量 `bbox()`，会产生大量同步测量。本版增加版本限定的纯文本测量插件：Canvas 预测换行并按字体/文本缓存，最终仍使用 SVG `bbox()` 校准真实尺寸，溢出时回退原算法。初始化等待字体就绪，保留全部节点和实际样式。另取消每次渲染结束都序列化完整树的行为，并让小地图缓存布局坐标，平移只更新视口。

插件同时替换该版本构造函数实际复制的方法对象和 prototype，原始计数必须验证 `svgMeasurements >= nodeCount`；仅替换 prototype 的早期尝试被构造函数覆盖，计数为零，不作为优化有效证据。内容居中使用构造节点时的规范宽高，避免极小缩放下浏览器 SVG 文字 bbox 失真后留下永久偏移，同时避免该次已附着 DOM 的同步测量。该替换仅在同步 layout 调用内生效，结束即恢复真实 bbox，导出和几何检查仍读取实际 SVG 边界；`layoutCorrections >= nodeCount` 用于验证路径命中。

几何回归见 `docs/mindmap-geometry-core-results.json`：9 种布局（包括 `timeline2`），25 节点强制 scale0.004 编辑并重新导入，再恢复 scale1，所有文字必须位于真实形状内；包含图标、标签、备注、链接、PNG 图片和四种图片位置。5000 节点的实际局部截图保存在 `docs/mindmap-5000-geometry-fixed.png`；修复前文字 x454.89..608.55，节点框 x629..811，修复后文字 x643..796.66，节点框不变。诊断运行可以证明行为与几何，未隔离其他测试的耗时不计入正式结果。

开发期曾观测 1000 节点初始化约 5153 ms；该轮等待和采样方法与本报告不同，不能据此计算严格加速倍数。未拿到结果的旧 5000 节点运行不作为卡死或通过证据。

## 复现命令

在 `frontend` 目录，以 Vite 测试服务 `http://127.0.0.1:60111` 为基础运行：

```powershell
$env:PLAYWRIGHT_MODULE_PATH='C:\Users\Lizy\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\node_modules\playwright\index.mjs'
$env:BROWSER_PATH='D:\Program Files\chrome-win64\chrome-win64\chrome.exe'
$env:MINDMAP_TEST_BASE='http://127.0.0.1:60111'
$env:MINDMAP_BENCH_SIZES='100,1000,5000'
node tools/run-mindmap-benchmark.mjs
```

独立核心与几何回归分别运行 `node tools/run-mindmap-core-checks.mjs`、`node tools/run-mindmap-geometry.mjs`。几何工具通过 `GEOMETRY_SIZES=25,1000,5000` 扩展数据规模，它是行为/边界检查，不能混用为性能统计。

执行时保持其他测试、构建和编辑器热更新空闲。设备、Chrome、Node、视口、UTC 时刻与浏览器单调时钟记录在原始 JSON 中。它测量指定桌面环境的一次确定性运行，不能替代跨设备、多次分布或带图片/富格式的生产数据测试。
