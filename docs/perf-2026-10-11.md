## 各模块代表性优化

- **N+1 / 计数下推**：blog 树/列表、todo 分类与计划计数、gamemap selectinload、pwsvc 项目/类型计数
- **全量拉取消除**：blog slug 祖先链（替代全表 map）、diary 统计 SQL GROUP BY 下推、todo stats SUM(CASE)、vault/pwsvc 列查询直出
- **ORM 快路径**：sdklogs 检索/写者驱动级 executemany、confcenter Core 语句缓存、todo dict 序列化（等价测试锁死）
- **读缓存**：todo /today 响应字节缓存（19 写端点 bump 纪元）、sdklogs sysnames/histogram/stats 5s TTL、apihub 规则/令牌/快照缓存
- **并发正确性顺带修复**：SQLite BUSY_SNAPSHOT 写 500 → vault/pwsvc/confcenter 重试全部归零
- **锁粒度**：apihub 限流 16 分片锁、KeySelector 身份快路径

## 骨架层改动（主线）

- 请求级 **trace**：纯 ASGI 中间件（X-Trace-Id 透传+回写）+ LogRecord 工厂全局注入 lizysdk context（所有模块日志自动带 trace_id）
- gzip compresslevel 9→6（starlette 默认 9，大响应每请求多耗 3-4ms CPU）
- 共享 bench_client 修复 autocannon 8 兼容（promisify + latency 单位 ms）

## 已知边界（实测证据）

1. **FastAPI 路由匹配地板 ~535 rps**（cProfile：`fastapi/routing.py _match` 为第一热点，239 条路由全量注册后从 1870 跌至 535）——所有模块的公共上限；提升需路由结构化/框架升级
2. SQLite WAL checkpoint 期写锁尖刺：模块级重试已兜底（500→0），根治需写队列化或 PG 后端
3. sdklogs kv 过滤 json_extract 全表扫：键空间任意无法预建表达式索引，缓解=先缩时间窗/sys_name
4. apihub gw 与 confcenter 降级路径的提升受共享 HTTP 栈（CORS/gzip/认证 ~65% 占比）限制
