## 四、压测发现并已修复的问题

1. **配额并发超卖窗口**（真 bug）：原实现"先查后增"，高并发同刻全通过检查会超卖。已改为**预占-退还**（检查即计数，网关侧彻底失败退还），200 并发实测恰好 50。回归 75/75 通过。
2. **默认探活路径误伤**（真产品缺陷）：API 未配 probe 时默认探 `GET /`，多数 API 该路径 404 →「一键探活全部」连续把健康 API 打成 down → 网关开始 503 拒绝其真实流量（本次压测实际触发：load-echo 被阻断 500 次）。已改为**默认探测 API 自身路径**，模板渲染失败记为探活失败而非崩溃。
3. **部署配置**：uvicorn 默认 access log 每请求同步写重定向 stdout（4631 行/348KB 垫在日志里）。验证对转发吞吐影响不大，但生产应加 `--no-access-log`（已写入 README）。
4. **排除项**：R1 曾现 157/300 放行——是固定窗口**跨分钟边界重置**的算法特性（100+57，设计文档已声明），非超卖；测试脚本已加窗口对齐。Windows Selector 循环实测与 Proactor 差异可忽略（转发 77 vs 76 rps），保持默认 Proactor（Selector 有 512 fd 上限，弃用）。

## 五、容量结论与建议

- **本机能力画像**：转发 ~110-140 rps/进程（CPU 上限，≈5-8ms CPU/请求：uvicorn 解析 + httpx 上游腿 + 响应重建）；纯内存路径（鉴权/限流/404）~3000 rps；管理台/探活余量巨大。
- **适用判断**：个人/小团队聚合场景（日均万级调用、上游本身几十至几百 ms）**完全够用**——上游慢时网关在等 IO，并发容量远高于本地 rps 数字。持续 60s 零错误、无内存泄漏，可长期运行。
- **使用建议**：① 并发连接建议 ≤200（c500 会积压超时崩塌；需要挡峰在外层加 nginx/连接整形）；② 追求 1k+ rps 转发：先在 Linux 部署复测（epoll + 更高单核性能），仍不够则按设计文档演进 Go/APISIX 数据面；③ 多实例部署前需先把限流器换 Redis 实现（接口已抽象）。

# 性能优化纪实（2026-10-09 增补）

目标：不增加 worker、不引入新组件，转发吞吐提升 ≥30%。

## 方法：先 A/B 实验再动手

隔离实验（`ab_transport.py`，同进程打同一上游）：httpx 单请求 3.38ms、并发崩塌至 ~120 rps；
原生 asyncio+h11（h11 是 httpx 既有依赖，零新增组件）单请求 0.81ms、c50 并发 2076 rps。
→ 锁定优化方向：替换上游转发腿。

## 实施内容

1. **快通道传输 `core/fasthttp.py`**：asyncio + h11 的 keepalive 连接池（按 scheme/host/port 分池），
   支持超时/一次重试/响应上限；复杂 transport（代理/HTTP2/自定义CA/重定向）自动回退 httpx 慢路径；
   异常统一抛 httpx 类型，管道捕获逻辑零改动。
2. **每目标并发连接封顶 128**：超额请求排队等连接（PoolTimeout 兜底），防止瞬时全量新建连接。
3. **热路径缓存**：凭证注入/URL 渲染按 (store.version, upstream, key) 缓存；信封改为手动 JSON 解析
   （省去每请求 pydantic 校验）；key 池加权展开表缓存；Timeout 对象缓存。
4. **冷却策略修复**：连接错误只在有备选 key 时计失败（连续 3 次才冷却 10s），
   唯一 key 绝不自我熔断（否则瞬时抖动 → 503 风暴）。

## 压测中揪出的隐藏 Bug（比提速更有价值）

- **h11 连接复用失效**：请求完成后 h11 状态是 DONE 而非 IDLE，必须显式 `Connection: keep-alive`
  或 `start_next_cycle()`。修复前每条连接用一次即关 → 一次 c500 产生 **13,561 个 TIME_WAIT**
  → Windows 临时端口耗尽（WinError 52）→ ConnectError 风暴 → （旧冷却逻辑下）单 key 熔断
  全量 503。一个缺失的头引发整条故障链。
- 修复后：c500 全程 **TIME_WAIT = 0**，持续压测仅 51 个（正常空闲过期）。

## 剩余瓶颈与边界

- 当前上限 ~1400 rps：三进程同机（压测客户端 + 网关 + 上游）CPU 竞争 + uvicorn/ASGI 入口层；
  鉴权拒绝路径 3400 rps 可视为框架入口上限的参照。
- 快通道不支持 gzip 自动解压（不发送 Accept-Encoding，按 identity 透传）与 HTTP/2 上游，
  需要 these 特性的上游走 httpx 慢路径自动回退。
- 目标 ≥30%：实际达成 **930%~1030%（10~12 倍）**。
